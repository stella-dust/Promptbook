# 产品需求 · V1

## 目标与范围

把在真实工具里得到的好结果记录下来，未来能通过图、分类或关键词重新找到 Prompt。本人录入要足够轻，公众浏览要足够安静。V1 的成功标准是：每天愿意增加记录，几周后仍能找到、复制、复现当时的提示词。

明确排除：站内文生图/视频、模型调用、公开注册、点赞评论、排行榜、收藏夹账号、生成任务队列、商业化、自动抓取全网内容。主页就是自己的精选库，无须再做一层“我的收藏”。

默认假设：网站和已发布记录公开只读，自己独占编辑。这个假设来自开源/贡献模式；公开不等于媒体默认允许任意再利用。需要完全私密的库时应另立私有数据方案，不在公开仓库里增加 `private: true`。

## 页面与路由

| 路由 | 页面 | 主要行为 |
|---|---|---|
| `/` | 素材首页 | 浏览、搜索、分类、类型、模型、排序 |
| `/p/{id}/` | 记录详情 | 看完整结果、切换输出、视频播放、复制、来源 |
| `/contribute/` | 贡献说明 | 下载模板、Issue/PR 入口、说明整理与发布流程 |
| `/admin/` | 个人管理入口 | 新建、当前浏览器草稿、已发布记录轻量列表 |
| `/admin/new/` | 新建记录 | Prompt + 实际媒体 + 元信息 |
| `/admin/edit/?id=...` | 编辑已有记录 | 读取 GitHub 最新文件与 SHA，发布更新 |
| `/404.html` | 缺失页面 | 简单返回，不生成伪详情 |

分类无需独立复杂页面。筛选写进 URL 查询参数：`q`、`kind`、`category`、`model`、`sort`，可分享和返回恢复。只有详情是长期稳定链接。ID 建立后不可随标题修改。

## 首页

默认最新排序。默认四列瀑布流，图片保持自然比例，卡片带标题、两行 Prompt、模型、复制。视频只载封面，不自动播放、不预取全部视频。

搜索范围：标题、Prompt 原文、tags、模型显示名；先做大小写归一后的普通文本匹配。搜索在本地轻量索引完成，避免逐次请求 GitHub/Worker。默认防抖 150ms；空输入表示不过滤。

分类为单主分类；标签可多选记录但 UI 不列全站所有标签。类目配置放 `content/taxonomy.json`，初始少量，不强行填满。没有内容的分类默认不显示。类型/分类/模型交集生效，结果数量反映实际筛选。

排序 V1 为最新 / 最早；不做虚假热度。归档记录不出现于列表和站内搜索，其历史和文件仍可能公开。

## 详情与真实结果

一条记录对应一段主要 Prompt 和同一次/同一配置的生成结果组，最多 8 个输出。V1 同条只包含图片或视频其中一种，降低表单和参数归属歧义。相同 Prompt 换模型时“复制为新记录”，用 `derivedFrom` 可选关联；不做复杂实验 Run 管理。

Prompt 必须保留原始换行和字符，不能自动翻译、缩写、优化。复制使用完整存储文本；卡片截断只是展示。可选保存追加的用户提示，但不能把后续编辑结果归功于初始 Prompt。

图片：原尺寸查看、预览、原文件下载；九宫格和长图能完整阅读。视频：原生播放、拖动、暂停、音量、全屏，默认 `preload=none`。输出有 alt 与可选说明。

“原始生成信息”区分平台名、用户填写的模型显示名、明确的模型 ID、证据来源、用户记录的时间。ChatGPT 页面没有明确给出的模型 ID/seed 不推断。媒体宽高和时长来自实际文件；其他生成参数保留原样，可为空。

## 录入表单

最少输入：标题、Prompt、结果文件、分类、模型显示名（允许明确填写“未知模型”）。平台可记忆上次选择，但需可见；如果没有值，显示“未记录”。默认示例不自动写入真实记录。

| 组 | 字段 | 行为 |
|---|---|---|
| 必填 | title、prompt.text、category、generation.modelLabel、outputs | 发布前验证 |
| 自动 | id、revision、createdAt、updatedAt、文件 MIME/bytes/width/height/duration | 可以查看，不伪造生成信息 |
| 常用 | platform、tags、summary、封面 | 可选，记忆上次分类/平台/模型 |
| 高级 | modelId、modelEvidence、generatedAt、parameters | 缺失时 null/空对象，禁止瞎填默认 seed |
| 高级 | negativeText、followups、notes、derivedFrom | 不改变 prompt.text |
| 参考输入 | role、媒体文件、caption | 默认不上传；仅主动授权公开的参考图 |
| 来源 | original/adapted/collected、author、url、contributor | 与提示词来源一致 |
| 使用说明 | Prompt 许可、媒体许可、备注 | 独立于代码 MIT，不自动赋 CC0 |

`generation.parameters` 接受键值 JSON，值只支持 string/number/boolean/null；不引入模型专用配置面板。UI 提供友好错误，不让用户看 JSON Schema 堆栈。

## 草稿与本地恢复

正式实现用 IndexedDB 保存草稿正文、表单状态和媒体 Blob，500ms 防抖，保存前估计配额。草稿列表仅当前浏览器可见，不跨设备同步；显著说明浏览器数据清理会删除草稿。请求 persistent storage 可作为增强，不能承诺永不丢失。

容量不足时保留文字，标记哪些媒体未保存并允许重新选择。未保存离页提示；可导出记录 JSON。图片/视频留存以原始下载文件和正式 R2 上传为准，浏览器草稿不当成唯一备份。

原型只实现文字草稿和会话内文件预览；Blob 持久化是 M2 必须完成的正式功能。

## 发布流程

发布前弹出一次清晰确认：将公开 Prompt、输出、被选中的参考图和来源信息；公开 Git 历史可能继续保留旧版本。

确认后：先检查表单 → 生成显示用缩略图 → 签名上传到私有暂存桶 → 验证并复制到公开媒体桶 → 写入 GitHub JSON → 等待网站构建 → 确认对应 revision 上线。表单有进度和逐文件错误；不得在 API 返回 commit 后立即提示“已上线”。

保存已有记录时携带读取时的 GitHub file SHA。远端被修改返回 409，提供“查看远端版本 / 导出本地内容”，不自动覆盖。失败后已上传成功的媒体可复用，不重复上传视频。

归档在 Web 提供，语义为从公开列表移除；V1 不提供误导性的“永久删除”。真正删除涉及 Git 历史、R2、CDN 和外部副本，按运维文档人工处理。

## GitHub 贡献

已有记录的文字修正可以 PR 修改 canonical JSON，合并后重建上线。新贡献通过 `submissions/*.json` 或 Issue，提供 Prompt、实际结果的暂存链接、模型说明和署名。维护者下载并检查文件，Web 导入提交模板，上传到自己的 R2，再发布为 canonical 记录。**新 submission 合并不会直接显示在公开首页。**

这个显式审核步骤避免给贡献者 R2 写权限，也避免媒体大文件长期进入 Git 历史。外部链接仅用于人工接收，不能直接作为线上图库的永久媒体地址。

## 初期容量目标

目标先按 1,000 条记录、每条 1–4 个结果设计；这只是测试规模，不是业务预测。浏览展示不需要数据库。构建从 JSON 自动生成列表、详情和小型索引，数量与分类来自数据，不手工维护 README 编号。

公开页不使用身份请求、统计追踪或第三方脚本；管理页不出现在 sitemap。公开文件本身是可下载/可复制数据，不能宣称“禁止爬取”即可保护内容。
